# 地址核对记录

所有地址均为相对 `Game.dll` 基址（`0x6F000000`）的 RVA。
“工具”一列的命令是 `tools/re/w3re.py`，可以自己复核。

## 1. 1.24E（build 6387）—— 全部逐条核对

### 1.1 JASS 原生函数（59 个）

来源：TuringY `native_offsets_6387.inc`，由 `tools/gen_offsets.py` 生成 `src/dll/NativeOffsets.inc`。
其中原版大象 1.24E 脚本用到的 30 个与脚本 `define(...)` 逐条一致（`tests/selftest.cpp` 自动比对），例如：

| 函数 | RVA | 原版脚本 |
|---|---|---|
| CreateUnit | 0x3C5D70 | `define(CreateUnit,game.dll+3c5d70)` |
| GroupEnumUnitsSelected | 0x3CF0D0 | `define(GroupEnumUnitsSelected,game.dll+3cf0d0)` |
| SetHeroLevel | 0x3C78B0 | `define(SetHeroLevel,game.dll+3c78b0)` |
| UnitAddAbility | 0x3C8DE0 | `define(UnitAddAbility,game.dll+3c8de0)` |
| FogEnable | 0x3BBD20 | `define(FogEnable,game.dll+3bbd20)` |
| ……（共 30 项，见 selftest） | | |

调用约定：全部 `__cdecl`，real 参数传 `float*`，real 返回值在 EAX（位模式）。
`aero::generic_c_call` 生成的汇编已核对（参数入栈顺序、调用方清栈）。

### 1.5 每帧挂钩（所有命令在这里执行）

原版 1.24E 脚本：`game.dll+4D3E30: jmp myhook_install / nop`，存根末尾 `mov [game.dll+0acecf0],ecx`；
原版 1.20E 脚本：`game.dll+4dd90`，原指令 `mov [game.dll+85ff20],ecx`。

| 项目 | 1.24E | 证据 |
|---|---|---|
| 挂钩点 `GAME_FRAME_HOOK` | 0x4D3E30 | 整个函数只有 `89 0D F0 EC AC 6F`（mov [0xACECF0],ecx）/ `C3`，16 字节对齐，可以 8 字节原子替换 |
| 调用者 | 0x39B964 / 0x39CC40 / 0x3B0D3E | 共 3 处：CWorldFrameWar3 构造函数 0x39B450（`xor ecx,ecx` 后调用，原版脚本据此“每次重新开始后重置全局组”）；每帧函数；0x3B09D0（只有 0x5C1B78 一处调用） |
| 每帧函数 | 0x39CBD0 | CWorldFrameWar3 虚表（0x9536D4）第 11 项（+0x2C）。`fld [esi+23Ch]` 取本帧时间并清零，`fadd`/`fstp [esi+390h]` 累加到总时间，然后 `call 0x53FCE0 / mov ecx,eax / call 0x4D3E30` |
| 返回地址 `GAME_FRAME_HOOK_RETURN` | 0x39CC45 | 上面那条 call 之后的 `fldz`；修改器只在返回地址等于它时执行（构造函数和开局那两次调用直接返回） |
| 全局变量 `GLOBAL_FRAME_HOOK_VAR` | 0xACECF0 | 挂钩前核对原始字节 `89 0D <基址+0xACECF0>` |

调用挂钩点时 x87 栈为空（0x39CC25 的 `fstp` 之后），存根用 `pushad / pushfd` 保存全部寄存器，修改器代码可以正常使用浮点。

**为什么不用窗口消息**：早期版本用 `PostMessage` + `WH_GETMESSAGE` 消息钩子让游戏主线程执行命令，在模拟进程里正常，
但实机测试（1.24E）时模块一直收不到消息，界面显示“游戏暂时无响应”，所有快捷键没有反应。
没有完整游戏的环境里无法确认消息具体在哪一环丢失；游戏的消息循环（0x6C6EC0）里还有自己的输入事件队列
（`[0xAE82E8]`/`[0xAE82EC]`）和过滤函数（0x6C2FB0），窗口消息这条路不可靠，所以改回原版实机验证过的每帧挂钩。

## 2. 1.20E（build 6074）

* JASS 原生函数：与原版 1.20E 脚本逐条一致（selftest 自动比对 15 项）。
* `CGameUI::world` 在 +0x3B0（= 0x3BC − 0xC，即 `GameUIField()` 的换算）：
  CGameUI 构造函数 `0xEAA70` 中 `new 0x668`（与 1.24E 的世界画面对象大小相同）后 `mov [esi+3B0],eax`，
  该对象构造函数 `0x1776F0` 初始化 `+0x310/+0x314`。
* 物品数据表在 0x870CC0（构造代码 `0x1D6CA4`：`[+0]` 虚表、`[+4]` 链表偏移、`[+0xC]` 首节点），
  TuringY 登记的 0x870CC4 偏了 4 字节。
* 人口上限缓存在 0x7E7838（与 1.24E 的 0xA6575C 作用相同，娱乐模式开启时立即写入）。
* 代码补丁取自原版脚本，原始字节已从 1.20E Game.dll 读出，写入前同样会校验。
* 尚未在真实 1.20E 游戏中运行测试。
